# Бэкенд: Google Apps Script + Google Sheets

Один файл `Code.gs` — веб-приложение, которое хранит **только факты**: оплаты, воронку, штат, отсутствия. Состояние питомцев считает клиент из этих фактов (`src/engine/`), поэтому повторная загрузка файла ничего не удваивает: слой за период просто заменяется.

## Развёртывание (делает человек, один раз)

1. Создайте пустую Google-таблицу. Её идентификатор — часть адреса между `/d/` и `/edit`.
2. В таблице: **Расширения → Apps Script**. Вставьте содержимое `Code.gs`; в **Настройки проекта** включите «Показывать файл манифеста» и вставьте `appsscript.json`.
3. **Настройки проекта → Свойства скрипта** добавьте:
   - `SPREADSHEET_ID` — идентификатор таблицы из шага 1;
   - `INITIAL_PIN` — первый админ-PIN, от 4 до 12 цифр.
4. Запустите функцию `setupSpreadsheet` (создаст листы с заголовками), затем `initAdminPin`. Вторая сохранит хеш PIN и **сотрёт `INITIAL_PIN`** из свойств; если админ-PIN уже задан, она остановится с ошибкой. Дальше PIN меняет только действие `changePin`.
5. **Развернуть → Новое развёртывание → Веб-приложение**: «Выполнять от имени» — я, «Доступ» — все. Адрес `…/exec` и есть адрес бэкенда.
6. PIN групп выдаёт действие `setGroupPins` (6 цифр на группу, **показываются один раз**, старые перестают работать). Запускайте его из админки (вкладка «PIN-коды») и передавайте руководителям лично.

PIN не отправляйте в чат, не кладите в URL и в репозиторий. В репозитории хранятся только код и вымышленные тестовые данные.

## Что публично

`GET /exec` открыт всем, у кого есть адрес. В ответе: сотрудники (полные ФИО и группа), оплаты `{date, group, author, invoice}`, воронка по сотрудникам и дням, отсутствия, ручные правки и расходы предметов `overrides` `{id, date, group, kind, delta}` по возрастанию `id`, `config`, служебные даты. **Нет**: сумм оплат, PIN, хешей и солей, причин исключения из рейтинга (их читает админ действием `getPrivate`), ключей повтора расходов `ref`. Номер счёта остаётся публичным: на нём держится правило «один счёт — одна оплата».

`GET /exec?since=<версия>` при неизменной версии отвечает `{ok:true, unchanged:true, version}` без данных.

## Действия (`POST`, тело JSON, заголовок `text/plain`)

Ответ: `{ok:true, …}` или `{ok:false, error}`; `error` — `invalid_pin`, `locked` (+`retryAfterSec`), `bad_request`, `server_error`.

| Действие | PIN | Что делает |
|---|---|---|
| `login` | админ | проверка админ-PIN |
| `changePin` | админ | `newPin` (4–12 цифр, не совпадает с PIN группы) |
| `setGroupPins` | админ | выпускает 6-значные PIN шести групп, возвращает их один раз |
| `groupLogin` | группы (`group`, `groupPin`) | сверяет PIN с хешем заявленной `group` (не из шести — `bad_request`); отвечает `{ok, group}` |
| `setProvisional` | админ | `date, group, count`: предварительное число оплат за день; только за дни после последнего импорта и не позже сегодня |
| `importPayments` | админ | `from, to, rows[{date, group, author, invoice}]`, `dryRun`: заменяет оплаты и предварительные числа за период; `to` — строго раньше сегодняшнего дня; не больше 62 дней. Строки вне `[from, to]` (выгрузка «хвостом» за сегодня или с прошлого месяца) отбрасываются и считаются в `ignored`; мусорная строка отклоняет весь файл |
| `importFunnel` | админ | `through, rows[{name, date, quality, long}]`: добавляет и обновляет по (сотрудник, дата), двигает `funnelThrough`; `through` раньше сегодняшнего дня. Дни после `through` (нули колонок без данных) отбрасываются и считаются в `ignored`; неизвестное ФИО или мусор отклоняют весь файл |
| `setStaff` | админ | `staff[{name, group?, shortName?, hireDate?, fireDate?, baseLevel?, hiddenFromRating?, transfers?}]`: добавляет и обновляет по ФИО (без учёта регистра и лишних пробелов) |
| `getPrivate` | админ | отдаёт то, чего нет в публичном GET: `hiddenReasons` — причины исключения из рейтинга по `employeeId` |
| `setConfig` | админ | `config` — частичный объект: сливается с сохранённым, неизвестное поле, дробное число и значение вне диапазона отклоняют запрос; допустимые поля и диапазоны — в `CONFIG_RANGES` в `Code.gs` |
| `setOverride` | админ | `date, group, kind` (`piles`, `medkits` или `toys`), `delta`: ручная дельта к кучкам, аптечкам или игрушкам группы; дата не позже сегодня, `delta` целое, не 0, по модулю не больше 20. Удалить правку нельзя — гасится компенсирующей. Отвечает `{ok, version, id}` |
| `useItem` | группы (`group`, `groupPin`) | `item` (`medkit` или `toy`), `ref`: РГ тратит предмет своей группы. Группа берётся из PIN, дата — сегодня на сервере. `ref` — случайная строка клиента (1–64 символа): повтор с тем же `ref` той же группы ничего не пишет и отвечает `duplicate: true`. Не больше 20 расходов группы в сутки. Остаток сервер не проверяет: расход при нулевом запасе движок пропускает |
| `setAbsence` / `removeAbsence` | админ | отпуск и больничный задним числом тоже допустимы |

PIN админа идёт в поле `pin`, PIN группы — в `groupPin` вместе с заявленной группой в `group`. PIN группы открывает только `groupLogin` и `useItem`; админские действия им не выполняются, и наоборот. Ошибки PIN считаются отдельно по каждой группе: перебор одной группы блокирует только её и не сбрасывается верным входом другой.

## Ограничения и договорённости

- **Однофамильцы по полному ФИО.** Сотрудника различает нормализованное ФИО (регистр и пробелы не важны); двух людей с одинаковым ФИО система не различит. Дубль внутри одного запроса `setStaff` отвечает `bad_request`; запрос позже обновит уже существующего сотрудника, а не заведёт второго.
- **Периоды импорта оплат — подряд.** Импорт только заменяет выбранный период; пропуск между двумя файлами остаётся пустым, пока не загрузят период, который его покрывает.
- **`through` воронки задаёт импорт.** В выгрузке будущие и ещё не заполненные дни стоят нулями и от «ничего не делали» не отличаются, поэтому дату, по которую данные настоящие, называет тот, кто грузит файл. Дальше этой даты питомцам не начисляются ни награды, ни штрафы. Повторный импорт с более ранним `through` отодвигает границу назад.
- **Руками в листах правьте только осознанно**, а после правки запустите `bumpVersion`: открытые страницы перечитывают данные, только когда растёт версия.
- **Счётчик неверных PIN — в `CacheService`.** После 5 ошибок подряд вход блокируется на 10 минут. Кэш Google не гарантированное хранилище, поэтому защита от перебора считается «по возможности», а не жёсткой. Админ-PIN и PIN каждой группы считаются раздельно.
- **`config`** хранится JSON-строкой в `Settings.config`; пока `setConfig` не вызывали (или ячейку испортили руками), в ответе `{}`, и клиент берёт умолчания. Правка действует на всю историю: пересчёт идемпотентный, даты вступления нет. Календарь игры (`startDate`, `endDate`, `nonWorking`) не правится.
- **Расходы и ручные правки** лежат в одном листе `Overrides` (`id, date, group, kind, delta, ref`): `piles`, `medkits`, `toys` — дельты админа, `useMedkit`, `useToy` — расходы РГ. Сервер не знает состояния питомца, поэтому расход при нулевом запасе тоже записывается; движок его пропускает.
- **Скорость.** Полный снимок на 60 сотрудников за три недели — порядка нескольких тысяч строк. Время ответа живого Apps Script нужно замерить после развёртывания; если окажется медленным, добавить кэш частями.

## Тесты и мок

Тесты выполняют настоящий `Code.gs` в Node поверх поддельных сервисов Google (`test/gas-harness.mjs`):

```bash
npx vitest run apps-script
```

Локальный стенд с демо-данными (вымышленные сотрудники, «сегодня» зафиксировано на 12.11.2026):

```bash
npm run mock-backend
```

Адрес — `http://localhost:8787/exec`. **Админ-PIN `1234` — только для мока**, в боевом развёртывании его нет. PIN шести групп мок выпускает при каждом запуске заново (случайные, нигде не печатаются и не хранятся): `startMockBackend()` возвращает их в `groupPins`, а в окне админки их можно выпустить заново во вкладке «PIN-коды». Страница игры: `http://localhost:5173/?backend=http://localhost:8787/exec&asOf=2026-11-12`.
