# Открытые ассеты для игр и как их забирать в Claude Code

Oct 23, 2026

## Коротко

Бесплатных открытых библиотек хватает на всё: персонажи, тайлы, UI, 3D-модели с анимациями, текстуры, звук. Лучшая отправная точка для обоих направлений — **Kenney** (2D и 3D, лицензия CC0). Для 2D-персонажей с готовыми анимациями лучше всего **Universal LPC**. Для 3D-персонажей с анимациями подойдут **Quaternius** и **KayKit**, для текстур и окружения — **Poly Haven** и **ambientCG**.

Claude in Chrome для загрузки ассетов — самый дорогой путь: каждый скриншот страницы уходит в контекст и съедает лимит. Правильнее так: Claude ищет ассет через API или WebFetch (это текст, а не картинки), качает архив через `curl` прямо в проект, распаковывает только нужные файлы и записывает лицензию в `CREDITS.md`. Chrome остаётся только для сайтов, где нужен вход в аккаунт (itch.io, Mixamo).

Следите только за лицензиями: CC-BY-SA и GPL требуют распространять производные работы под той же лицензией. Для внутренних игр компании это обычно не проблема, но авторов в титрах указать нужно.

Связка с Blender MCP: персонаж Quaternius или KayKit с готовой анимацией → Claude импортирует его в Blender, ставит ортографическую камеру и рендерит 8 направлений покадрово → скрипт склеивает спрайт-лист. Так один и тот же персонаж работает и в 3D-игре, и в 2D-игре бесплатно.

## Звук, шрифты, палитры

- **Звуки интерфейса и игры:** аудионаборы [Kenney](https://kenney.nl/assets/category:Audio) (CC0) — клики, монетки, джинглы.
- **Большая база звуков:** [Freesound](https://freesound.org) — у каждого звука своя лицензия CC, есть API с бесплатным ключом.
- **Ретро-звуки кодом:** jsfxr или ZzFX — Claude генерирует 8-битные эффекты параметрами прямо в коде, файлы вообще не нужны.
- **Шрифты:** [Google Fonts](https://fonts.google.com) (OFL) и пиксельные шрифты Kenney (CC0). Для русского текста проверяйте кириллицу: у Google Fonts есть фильтр по языку, а у пиксельных шрифтов кириллица часто отсутствует.
- **Палитры:** [Lospec](https://lospec.com/palette-list) — готовые пиксель-палитры. Полезно, чтобы свести ассеты из разных источников к одному стилю: Claude перекрашивает спрайты в выбранную палитру скриптом.

## Как Claude Code должен забирать ассеты

Почему Chrome — не лучший путь: Claude in Chrome работает через скриншоты и клики. Каждый скриншот — это картинка в контексте, а картинки дорогие, плюс много шагов на простую загрузку. По качеству результата разницы нет: файл тот же, просто достаётся дешевле.

**Порядок, от дешёвого к дорогому:**

1. **Локальная библиотека.** Один раз скачайте любимые наборы (Kenney, Quaternius, KayKit, LPC) в папку вроде `~/game-assets`. Claude ищет по именам файлов и копирует нужное в проект. Ни сети, ни картинок в контексте.
2. **API.** Где он есть, Claude делает один `curl` и сразу кладёт файл на место:
   - `curl -o assets/ui/icons/sword.svg https://api.iconify.design/game-icons/broadsword.svg`
   - `curl -H "User-Agent: MyGames/1.0" https://api.polyhaven.com/files/<id>` → ссылки на файлы → `curl` нужного разрешения
   - Poly Pizza и Freesound — то же, с ключом из переменной окружения.
3. **WebFetch + curl.** Для сайтов без API (Kenney, OpenGameArt) Claude читает страницу как текст, находит прямую ссылку на zip и лицензию, качает `curl -L`, распаковывает только нужные файлы.
4. **Blender MCP** — для Poly Haven прямо в сцену и для рендера 3D в спрайты.
5. **Chrome или руками** — только когда нужен вход или кнопка «сколько заплатить» (itch.io, Mixamo, Sketchfab). Часто быстрее скачать zip самому и положить в проект.

**Правила, которые стоит дать Claude:**

- Не открывать каждую картинку, чтобы «посмотреть». Размеры и сетку кадров узнавать скриптом. Если нужно выбрать визуально — собрать одну картинку-превью со всеми кандидатами и смотреть её один раз.
- Поиск ассетов отдавать субагенту на Sonnet: он роется в сайтах, а в основной контекст Opus возвращает только пути к файлам и лицензии. На качество игры это не влияет: код по-прежнему пишет Opus.
- Каждую загрузку сразу записывать в `CREDITS.md`: источник, автор, лицензия, ссылка.

Эти правила удобнее всего оформить как скилл `game-assets`: тогда Claude будет следовать им в каждом проекте без напоминаний.

## Структура папок и лицензии

```
assets/
  _raw/          # скачанные архивы, в .gitignore
  sprites/       # персонажи и спрайт-листы + JSON кадров
  tiles/
  ui/            # иконки, кнопки, шрифты
  models/        # .glb
  textures/
  audio/
CREDITS.md       # источник | автор | лицензия | ссылка | файлы
```

- В проект кладём только используемые файлы, а не весь набор: игра легче, Claude не теряется в сотнях ненужных файлов.
- 3D держим в `.glb`: один файл с текстурами и анимациями, понимается и Three.js, и Godot.
- Лицензии по строгости: **CC0** — бери и пользуйся; **CC-BY / OGA-BY** — укажи автора; **CC-BY-SA / GPL** — укажи автора и давай переработки под той же лицензией; **«только некоммерческое»** — для игр компании лучше не брать, это серая зона.

Источники проверки: [Poly Haven API](https://polyhaven.com/our-api), [Universal LPC Generator](https://github.com/LiberatedPixelCup/Universal-LPC-Spritesheet-Character-Generator), [Poly Pizza API](https://skills.sh/editframe/skills/poly-pizza-api), [обзор бесплатных текстур и HDRI](https://app.cinevva.com/guides/free-textures-hdris-materials). Лицензии Kenney, Quaternius, KayKit, game-icons, Mixamo и Freesound указаны по памяти — перед использованием сверьте на сайте.

## Сервисы генерации 3D: Tripo, Meshy, Hi3D

Рейтинг из поста разработчика: 🥇 Hi3D, 🥈 Meshy, 🥉 Tripo. Все три делают 3D из картинки или текста, и у всех есть бесплатный тариф, с которого модели **можно скачать легально** под лицензией CC BY 4.0: модель публичная, в титрах нужно указать сервис.

| Сервис | Бесплатно | Хватает на | Лицензия бесплатного тарифа | Форматы |
| --- | --- | --- | --- | --- |
| [Hi3D](https://hi3d.ai) | 100 кредитов **на всё время**, до 10 генераций, хранит 7 моделей | \~10 моделей, дальше только платно (цены по запросу) | CC BY 4.0, публичные | FBX, GLB, OBJ, STL, USDZ |
| [Meshy](https://www.meshy.ai) | 100 кредитов **в месяц** (сброс 1-го числа). Image→3D — 20 кредитов (Lite — 10). Ремеш, риггинг и базовые анимации бесплатно | 5–10 моделей в месяц **с ригом и анимациями** | CC BY 4.0, коммерческое использование с атрибуцией | GLB, FBX и др. |
| [Tripo](https://www.tripo3d.ai) | 300 кредитов в месяц, 1 задача за раз, история хранится 1 день | Выгоднее всего по объёму | CC BY 4.0, публичные; про коммерцию на бесплатном тарифе источники расходятся | Ограниченный набор |

Для внутренних игр компании CC BY 4.0 подходит: достаточно строки в `CREDITS.md` и в титрах. Минус один: персонаж будет публично виден в галерее сервиса, поэтому не загружайте туда картинки с логотипами и лицами сотрудников.

**Локальная альтернатива без лимитов:** открытые Hunyuan3D (Tencent) и TRELLIS (Microsoft). По опыту пользователей Hunyuan3D нужно примерно 12–16 ГБ видеопамяти (облегчённые turbo-версии — 8–10 ГБ), одна модель генерируется около 10 минут на RTX 3060. Результат чуть хуже Tripo: топология грязнее, масштаб не сохраняется, бывают лишние пальцы, задняя сторона «додумана». В Blender MCP Hunyuan3D встроен через облачный API Tencent (нужны ключи), а не локально, поэтому локальную модель запускайте отдельно и импортируйте готовый GLB.

## Серый метод из поста (для справки)

Автор поста предлагает два способа забрать модель с этих сервисов без подписки, плюс мультиаккаунты для обхода лимитов:

1. Браузерное расширение WebGLRipper, которое перехватывает модель из 3D-просмотрщика на странице.
2. Инструменты разработчика браузера: вкладка Network, фильтр по GLB, открыть найденный файл.

**Почему это не включено в правила и установщик:**

- **Риск для игр компании.** Оба способа и мультиаккаунты нарушают условия сервисов. Лицензии на такую модель нет, и аккаунт могут заблокировать.
- **Безопасность.** Расширение с доступом ко всем страницам, установленное вручную из архива, видит всё, что вы открываете в браузере, включая рабочие системы.
- **Качество.** Из просмотрщика часто приходит облегчённая превью-версия: меньше полигонов, сжатые текстуры, без рига.
- **В большинстве случаев он не нужен.** У Meshy и Tripo скачивание с бесплатного тарифа и так бесплатное и легальное (CC BY 4.0), а если нужно больше — локальный Hunyuan3D или TRELLIS.

## Как работать с Blender MCP и не жечь лимиты

Реальный опыт: в одном публичном тесте «сделай пончик с кофе» Claude через Blender MCP потратил 60% лимита тарифа Max 5x за 2 часа, и сессия развалилась, когда контекст кончился. Съедает не одна команда, а накопленная история: каждый шаг, каждая ошибка и каждый скриншот едут в каждом следующем запросе.

**Главное:** повторяемая работа идёт через готовые скрипты в Blender без интерфейса, а не через MCP по шагам. Скрипт возвращает короткий JSON, а шум Blender в контекст не попадает. Вам не нужно разбираться в Blender: он должен быть просто установлен, а для MCP — открыт с запущенным сервером (N → MCP for Blender → Start MCP Server).

| Задача | Как делает Claude |
| --- | --- |
| Проверить модель | скрипт `check_asset.py` |
| Привести к стандарту и выгрузить GLB | скрипт `prepare_glb.py` |
| Сделать спрайт-листы из 3D | скрипт `render_sprites.py` |
| Собрать сцену, поправить материал, добавить ассет с Poly Haven | Blender MCP |

**Правила для MCP:**

1. **Не моделировать с нуля.** Моделирование «из кубиков» кодом — самое дорогое и самое слабое место. Порядок: готовая модель из библиотеки → сгенерированная → и только потом своя. Blender — для доработки, рига, экспорта и рендера.
2. **Проверять числами, а не картинками.** Состояние сцены — текстом (`get_scene_info`). Картинка (`look`) — один раз в конце, маленькая (512 пикселей), с нескольких сторон сразу.
3. **Мелкие шаги.** Один небольшой вызов кода за раз: большие падают по таймауту.
4. **Сохраняться после каждого удачного этапа** в `work/<имя>.blend`. Код в MCP выполняется прямо в живой сцене, отмены нет.
5. **Одна сессия = один ассет.** Готово → обновить `PLAN.md` → `/clear`. Новую сессию начинать с сохранённого .blend, а не с длинной истории.
6. **Платная генерация выключена.** В новой версии MCP есть `generate_3d` (Meshy, Hyper3D, Hunyuan3D): каждый вызов тратит деньги или месячные генерации, поэтому только по явной просьбе.
7. **Качество не страдает:** план и сложные решения по-прежнему за Opus, а проверки делают скрипты — они строже глаза, потому что считают каждую грань.

Пакет `blender-mcp` переименован в `mcp-for-blender`. Установщик использует новое имя, телеметрия выключена. Сервер аддона без пароля, поэтому порт 9876 должен быть доступен только локально.

## Каким должен быть результат

**Готовая 3D-модель** (всё ниже проверяет `check_asset.py`, большую часть чинит `prepare_glb.py`):

- [ ] Один файл `.glb`: меш, материалы, текстуры и анимации внутри.
- [ ] Масштаб: 1 единица = 1 метр. Персонаж 1.6–1.9 м (или как принято в игре), предметы в реальном размере.
- [ ] Точка опоры внизу по центру, в (0,0,0): модель стоит на полу, а не висит и не проваливается.
- [ ] Трансформации применены: масштаб 1, поворот 0.
- [ ] Лицом к −Y в Blender (это +Z в glTF и Three.js).
- [ ] Нормали наружу, нет перевёрнутых и невидимых граней.
- [ ] Треугольников для веб-игры: персонаж 3–15 тыс., предмет 0.3–5 тыс., фон 0.1–1 тыс. (моя оценка для браузера; для десктопных игр бюджеты выше).
- [ ] Материалы: Principled BSDF и картинки. Процедурные текстуры запечены.
- [ ] Текстуры до 2048 (для веба 1024), лучше степени двойки.
- [ ] Риг: одна арматура, меш её дочерний объект. Анимации — отдельные экшены с понятными именами (Idle, Walk, Run, Attack), зациклены.
- [ ] Размер файла разумный: для веба сжать через gltf-transform (meshopt + webp).

**Готовые спрайты из 3D** (делает `render_sprites.py`):

- [ ] Одна камера, один масштаб и один свет на все кадры: персонаж не «прыгает» и не меняет размер.
- [ ] Ноги в одном и том же месте кадра во всех кадрах и направлениях.
- [ ] Строки листа — направления (S, SW, W, NW, N, NE, E, SE), столбцы — кадры. `sheet.json` с размером кадра и fps, чтобы цикл длился как в исходной анимации.
- [ ] Прозрачный фон, цвета как в текстурах (режим Standard, а не AgX — иначе цвета тускнеют).
- [ ] Для пиксель-арта: без сглаживания и полупрозрачной каймы (`--pixel`), кадр 32–64 px. В движке включить пиксельный режим (в Phaser `pixelArt: true`).
- [ ] Глазами смотрим одну картинку `preview.png`, а не каждый кадр.

## Частые ошибки Claude в Blender: что перепроверять

Собрано из публичных тестов и чек-листов по игровым ассетам, плюс то, что я поймал сам, пока писал и проверял скрипты.

| Ошибка | Как ловить |
| --- | --- |
| Говорит «готово», хотя проблемы остались | Готово только когда `check_asset.py` на **итоговом GLB** вернул `"status": "OK"` |
| Масштаб: объекты в сотни раз больше (FBX/GLB в сантиметрах), предметы протыкают друг друга | Высота в отчёте против ожидаемой (`--height`) |
| Переделывает то, о чём не просили: форму, цвета, окружение | В конце задачи — список изменённых объектов; что не в задаче — откатить из сохранённого .blend |
| Камера и свет: пересвет, слишком крупный план, розовая заливка | Для спрайтов камеру и свет ставит скрипт, а не Claude. Розовый цвет = потерянная текстура |
| Процедурные материалы молча пропадают при экспорте в GLB | `prepare_glb.py` пишет предупреждение. Проверка уже выгруженного GLB это не увидит: материал там уже «чистый» |
| Не применены масштаб и поворот: в движке модель другого размера или лежит на боку | `check_asset.py` |
| После применения масштаба к ригу анимация «разлетается»: сдвиги костей остаются старыми | `prepare_glb.py` пересчитывает их сам. Проверено: размеры в анимации совпали с исходными |
| В Blender 4.4+ экшен без «слота» не проигрывается, а старый код с `action.fcurves` ломается | В скриптах учтено. Если Claude пишет код анимаций сам — пусть проверит версию Blender |
| Модель смотрит не в ту сторону | В `preview.png` верхний ряд (S) — лицом к зрителю; иначе `--rotate 180` |
| Цвета в рендере тусклые | Режим цвета Standard вместо AgX — скрипт ставит сам |
| Связанные копии (Alt+D): правка одной меняет все | При правке одного объекта проверять `users` у меша |
| Модификаторы не применены, движок их не понимает | Экспорт с применением модификаторов в `prepare_glb.py` |
| Склеивает «дубли вершин» в импортированной модели и ломает швы UV | У GLB/FBX дубли — норма; склеивать только в своей модели |
| Оставляет объект в Edit Mode — следующие операции падают | Скрипты сами переключают в Object Mode |
| Генерированные модели (Meshy, Tripo, Hunyuan3D): лишние пальцы, «додуманная» спина, случайный масштаб, грязная сетка | Всегда через `prepare_glb.py --height`, бюджет треугольников, один `look` с нескольких сторон |

## Установщик asset-kit и правила для Claude Code

Архив `asset-kit.zip` лежит рядом с `game-kit` в файлах проекта (`claude-kit/`). Он дополняет game-kit и ничего в нём не перезаписывает.

**Установка:**

1. Поставить бесплатные [Blender](https://www.blender.org/download/) 4.2 LTS или новее и [uv](https://docs.astral.sh/uv/getting-started/installation/).
2. Распаковать архив в корень проекта игры и запустить `bash setup-assets.sh` (на Windows — из Git Bash или WSL).
3. Перед работой с MCP: в Blender `N` → вкладка MCP for Blender → Start MCP Server. Проверить `/mcp` в Claude Code.

**Что делает установщик:** находит Blender, ставит и включает аддон, подключает MCP-сервер к проекту (`.mcp.json`, телеметрия выключена), создаёт папки `assets/` и `CREDITS.md`, дописывает 4 строки правил в `CLAUDE.md`. Повторный запуск безопасен.

| Что внутри | Зачем |
| --- | --- |
| Скилл `game-assets` | Где брать бесплатные ассеты, как качать через API и `curl` без браузера, лицензии, `CREDITS.md` |
| Скилл `blender-assets` | Правила MCP, стандарт модели и спрайтов, чек-лист ошибок из этого документа |
| `check_asset.py` | Проверка модели, ответ — короткий JSON со списком проблем |
| `prepare_glb.py` | Масштаб под высоту, опора в (0,0,0), применённые трансформации, экспорт GLB с анимациями |
| `render_sprites.py` | 3D → спрайт-листы: 1/4/8 направлений × N кадров, `sheet.json`, `preview.png`, режим пиксель-арта |
| `run.sh` | Запускает скрипт в Blender без интерфейса и возвращает только итог и ошибки |

**Как проверено.** Скрипты прогнаны в Blender 5.2 без интерфейса на модели лисы из официальных примеров glTF (риг, 3 анимации) и на модели с нарочными ошибками: проверка нашла все ошибки, подготовка исправила всё, кроме процедурной текстуры (о ней предупреждает), спрайт-листы собираются. Установщик прогнан в тестовом проекте. **Не проверено** на настоящем Blender с интерфейсом: автоматическое включение аддона, вызовы через MCP и скорость Eevee на видеокарте. Если аддон не включится, установщик скажет, что сделать вручную.
