# Экономия лимитов Claude Code

Oct 23, 2026 · @Ignat

## Коротко

Лимит тратится не на ваши сообщения, а на то, что **каждый запрос заново отправляет весь контекст**: системный промпт, CLAUDE.md, всю историю и результаты инструментов. Один ваш запрос — это десятки запросов к модели (каждое чтение файла, запуск сборки, правка). У Opus 5.5 нативное окно 1M токенов, и автокомпакт по умолчанию срабатывает только около 967K, поэтому длинная сессия к концу гоняет сотни тысяч токенов на каждый шаг. Добавьте сюда Opus на всё (включая субагентов), скриншоты игры в контексте и промахи кэша после перерывов — и 5-часовой лимит уходит за час.

Три действия дают основной эффект: **ограничить окно контекста**, **делать /clear между задачами** и **перевести рутину на Sonnet, оставив Opus советником**.

## Что съедает лимит в геймдеве

1. **Раздутый контекст.** Сессия «весь день про одну игру» без /clear. Каждый шаг перечитывает всё.
2. **Opus на всё.** Субагенты наследуют модель сессии, так что они тоже работают на Opus.
3. **Картинки.** Скриншоты игры, спрайты, скриншоты из Playwright. Каждая картинка остаётся в контексте и едет в каждом запросе.
4. **Промахи кэша.** Перерыв дольше часа, смена модели посреди задачи, подключение MCP-сервера: следующий запрос обрабатывает весь контекст заново по полной цене.
5. **Многословный вывод.** `npm install`, сборка, логи, тесты целиком.
6. **Фоновое.** Субагенты, agent teams (около 7x токенов), `/loop`, длинный CLAUDE.md, лишние MCP-серверы.

## Сначала диагностика (5 минут)

- `/usage` → разбивка за день или неделю (клавиши `d` / `w`): какая доля ушла на скиллы, субагенты, плагины, MCP, и строки рекомендаций. Клавиша `f` применяет то, что Claude Code может применить сам.
- В том же `/usage` строка **Prompt cache (main)**: доля токенов из кэша, число промахов и их вероятная причина.
- `/context` — что именно сидит в контексте прямо сейчас.
- `/insights` — отчёт о ваших привычках по последним сессиям.
- Статуслайн с процентом заполнения контекста (`/statusline`), чтобы видеть рост постоянно.

## Топ-10 по эффекту

| # | Что сделать | Эффект | Как |
| --- | --- | --- | --- |
| 1 | Ограничить окно автокомпакта до 200K | Очень высокий | `"autoCompactWindow": 200000` в settings.json или `/autocompact 200` |
| 2 | `/clear` между задачами | Очень высокий | Одна механика, экран или баг = одна сессия. Перед этим `/rename`, вернуться через `/resume` |
| 3 | Sonnet 5.5 основной, Opus советник | Высокий | `/model sonnet` и `/advisor opus`: Sonnet делает рутину, Opus подключается на решениях и проверке |
| 4 | Субагенты на дешёвых моделях | Высокий | `model: haiku` или `sonnet` во frontmatter своих агентов, или `CLAUDE_CODE_SUBAGENT_MODEL` для всех |
| 5 | Не задирать effort | Высокий | У Opus 5.5 по умолчанию `medium`. `high`/`xhigh`/`max` только на сложную архитектуру; на рутину `/effort low` |
| 6 | Меньше картинок в контексте | Высокий для игр | Скриншот только когда нужен, обрезанный и маленький. В Playwright просить текстовый snapshot DOM, а не скриншот |
| 7 | Фильтровать вывод сборки и тестов | Средний | Хук PreToolUse (ниже) или субагент «log-reader» на Haiku |
| 8 | Лёгкий CLAUDE.md | Средний | До 200 строк. Подробные процедуры перенести в скиллы, они грузятся только по вызову |
| 9 | Отключить лишние MCP | Средний | `/mcp` → выключить неиспользуемые. Где есть CLI (`gh`, `gcloud`), он дешевле |
| 10 | Беречь кэш | Средний | Модель и effort выбирать в начале сессии. Уходите больше чем на час — сначала `/compact` или `/clear` |

## Готовые настройки

Файл `~/.claude/settings.json` (для всех проектов) или `.claude/settings.json` в репозитории игры:

```json
{
  "model": "sonnet",
  "advisorModel": "opus",
  "autoCompactWindow": 200000,
  "effortLevel": "medium",
  "env": {
    "CLAUDE_CODE_SUBAGENT_MODEL": "sonnet"
  }
}
```

Что это даёт: основная работа на Sonnet 5.5, Opus 5.5 подключается сам в ключевых точках, контекст сжимается на 200K вместо почти 1M, субагенты не уходят на Opus. Если хочется остаться на Opus, оставьте `"model": "opus"`, но первые две строки про окно и effort всё равно поставьте. Альтернатива советнику: `"model": "opusplan"` (Opus в plan mode, Sonnet при исполнении). Учтите, что каждое переключение plan mode при opusplan сбрасывает кэш.

В CLAUDE.md проекта добавьте блок, чтобы компакт не терял важное:

```markdown
# Compact instructions
Сохраняй: текущую задачу, изменённые файлы, решения по игровой механике, нерешённые баги. Логи и вывод сборки не сохраняй.
```

## Хук: только ошибки из тестов и сборки

В settings.json:

```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash",
        "hooks": [{ "type": "command", "command": "~/.claude/hooks/filter-test-output.sh" }] }
    ]
  }
}
```

Скрипт `~/.claude/hooks/filter-test-output.sh` (не забыть `chmod +x`):

```bash
#!/bin/bash
input=$(cat)
cmd=$(echo "$input" | jq -r '.tool_input.command')
pattern='^(npm test|npm run build|npx vitest|pytest)( [^;&|<>`$#\\[:cntrl:]]*)?$'
if [[ "$cmd" =~ $pattern ]]; then
  filtered="$cmd 2>&1 | grep -A 5 -E '(FAIL|ERROR|error)' | head -100"
  echo "$input" | jq --arg f "$filtered" '{hookSpecificOutput: {hookEventName: "PreToolUse", updatedInput: (.tool_input + {command: $f})}}'
else
  echo "{}"
fi
```

Проверка: `/hooks` должен показать хук в PreToolUse. Шаблон взят из официальной документации, список команд подставьте свои.

## Свои субагенты

Субагент держит многословную работу в своём контексте и возвращает в основную сессию только сводку. Файлы кладутся в `.claude/agents/` проекта.

`.claude/agents/log-reader.md`:

```markdown
---
name: log-reader
description: Запускает сборку, тесты или читает логи и возвращает только ошибки с файлом и строкой. Использовать для любой сборки и прогона тестов.
model: haiku
tools: Bash, Read, Grep
---
Запусти указанную команду. Верни не больше 20 строк: ошибки, файл:строка, одна фраза о вероятной причине. Полный вывод не пересказывай.
```

`.claude/agents/code-scout.md`:

```markdown
---
name: code-scout
description: Находит, где в проекте игры реализовано X, и возвращает список файлов с короткими пояснениями. Использовать перед правками в незнакомой части кода.
model: haiku
tools: Read, Grep, Glob
---
Найди релевантные места. Верни список путей и по строке на каждый. Код целиком не цитируй.
```

Ограничение: субагенты тоже тратят лимит, просто дешевле. Не просите «запусти 5 агентов параллельно» без нужды, а agent teams держите выключенными.

## Скиллы, которые окупаются

Скилл загружается только когда нужен, поэтому он дешевле длинного CLAUDE.md и дешевле, чем каждый раз давать Claude исследовать проект заново.

- **game-architecture** — устройство вашего движка или шаблона: структура папок, главный цикл, где сцены, где ассеты, соглашения по именам. Claude получает это сразу, а не читает 15 файлов.
- **new-department-game** — ваш повторяющийся процесс «игра для отдела»: шаблон проекта, чек-лист механик, сборка, деплой. Хорошо экономит на однотипных проектах.
- **sprite-pipeline** — как подключать новые спрайты: размеры, атласы, именование, куда класть. Это же место для будущего решения по генерации персонажей.

Создать скилл можно через встроенный skill-creator: попросите «сделай скилл по этому процессу» в конце удачной сессии. Встроенные `/simplify` и `/code-review` запускайте точечно, а не после каждой правки.

Для TypeScript/JavaScript игр стоит поставить плагин code intelligence (LSP): переход к определению заменяет grep и чтение нескольких файлов, а ошибки типов видны сразу после правки.

## Привычки на каждый день

- Пишите конкретно: «добавь двойной прыжок в `player.ts`, `jump()`», а не «улучши управление». Расплывчатая просьба запускает сканирование всего проекта.
- Сложную фичу начинайте в plan mode (Shift+Tab): дешёвое исследование и план до кода, без переделок.
- Ушёл не туда — сразу Esc, затем `/rewind` (двойной Esc). Это дешевле, чем `/compact`, потому что откат попадает в уже прогретый кэш.
- `/compact` делайте сами в естественной паузе между задачами, а не ждите автокомпакта посреди работы. Для свежего старта `/clear` бесплатен.
- Не переключайте модель посреди задачи: у каждой модели свой кэш, следующий ход пойдёт по полной цене. Смена effort на моделях 5.5 кэш не ломает.
- Давайте Claude способ проверить себя (тест, ожидаемый результат), чтобы не было лишних кругов исправлений.

## Чего избегать

- Agent teams, `/loop` и workflow без явной нужды: они тратят токены даже когда вы не смотрите.
- Сессию на Opus с `xhigh`/`max` «на всякий случай».
- Возвращение к огромной старой сессии через `/resume` после долгого перерыва: первый же запрос и `/compact` пойдут без кэша.
- Пачки скриншотов и спрайтов в одной сессии.

## Качество без перерасхода

Экономить стоит на исполнении, а не на мышлении. Самый дорогой токен тот, что ушёл на переделку бага. Поэтому сильная модель думает над планом, сложными багами и финальной проверкой, а более дешёвая исполняет уже готовый план.

| Задача | Модель | Effort | Почему так |
| --- | --- | --- | --- |
| Новая игра или механика: дизайн и план | Opus 5.5 в plan mode | high | Ошибка в плане потом повторится во всей реализации |
| Реализация по готовому плану | Sonnet 5.5 + `/advisor opus` | medium | План уже снял неопределённость, Opus подключится на развилках |
| Сложный баг: физика, состояние, тайминги | Opus 5.5 | high | Нужен поиск корневой причины, а не заплатка |
| Мелкие правки: тексты, цифры баланса, цвета, вёрстка | Sonnet 5.5 | low | Думать не над чем |
| Поиск по коду, логи, прогон тестов | Субагент на Haiku | — | Только читает и пересказывает, код не пишет |
| Проверка перед сдачей отделу | Opus (советник или `/code-review`) | high | Дешевле, чем баг, найденный игроками |

Где экономить нельзя:

- **План и сложные баги.** Effort и Opus тут остаются. Именно эти шаги дают ваши проекты «без багов».
- **Проверка.** Тесты, логи консоли и проверку перед «готово» не отключайте. Хук из раздела выше режет только шум, ошибки он пропускает.
- **Код пишет минимум Sonnet.** Haiku только ищет и читает.

Как не потерять нить при частом `/clear`: перед очисткой просите Claude записать состояние в `PLAN.md` (что сделано, что дальше, принятые решения). Новая сессия читает один короткий файл вместо часовой истории. Короткий контекст сам по себе помогает качеству: в сотнях тысяч токенов старой истории модель хуже держит важные детали.

Переходите постепенно. Сначала сделайте одну игру по новой схеме и сравните два числа с прежними: расход в `/usage` и число багов после сдачи. Если качество просело, верните Opus на реализацию, а всё остальное (окно 200K, `/clear`, субагенты) оставьте.

### Что не ставить или запускать редко

- **code-review** (4 параллельных агента) и **pr-review-toolkit** (6 агентов): хорошо ловят баги, но дорогие. Запускайте один раз перед сдачей игры.
- **ralph-loop**: зацикленная автономная работа, съедает лимит быстрее всего.
- **Superpowers: dispatching-parallel-agents и subagent-driven-development** на маленьких играх: на каждую задачу новый субагент и ревью.
- **Каталог wshobson/agents целиком**: десятки агентов, большинство вам не нужны.

Скиллы из чужих репозиториев — это инструкции и иногда скрипты, которые модель выполнит. Перед установкой пролистайте SKILL.md, это пара минут. Числа звёзд и установок взяты со страниц на 23 октября 2026.

## Память и поиск скиллов

Оба инструмента стоит ставить, но claude-mem с настройками по умолчанию тратит лимит Claude. Его нужно переключить на другого провайдера.

| Инструмент | Что делает | На что смотреть |
| --- | --- | --- |
| [claude-mem](https://github.com/thedotmack/claude-mem) (\~102k ★, Apache 2.0) | Хуки записывают, что делал агент. Записи сжимаются моделью и хранятся локально в SQLite. В новой сессии нужное подмешивается в контекст, и есть поиск по прошлым сессиям | Провайдер по умолчанию — Claude, то есть каждое сжатие идёт из вашего лимита. Ставьте с `--provider gemini` (бесплатный ключ AI Studio). Телеметрия включена по умолчанию, выключается `npx claude-mem telemetry disable` |
| [find-skills](https://www.vibeindex.ai/skills/vercel-labs/skills/find-skills) (vercel-labs/skills, \~3.5 млн установок) | На просьбу «найди скилл для X» ищет по каталогу skills.sh и ставит найденное | Сам скилл лёгкий (5 КБ). Найденные скиллы работают с полными правами агента, так что SKILL.md перед установкой стоит просмотреть |

Нужен ли вам claude-mem: в Claude Code уже есть встроенная автопамять, а в наборе есть `PLAN.md`. Для одной игры этого обычно хватает. claude-mem полезен, когда проектов много и хочется искать «как мы делали таблицу лидеров в прошлой игре». Поэтому в наборе он ставится отдельным флагом `--with-mem`.

## Граф знаний: graphify

[graphify](https://pypi.org/project/graphifyy/) строит по проекту граф: классы, функции, импорты и вызовы. Claude спрашивает граф и получает короткий ответ с файлами и строками вместо того, чтобы читать файлы целиком. На тестовой игре на вопрос «как работает прыжок» он вернул 10 узлов с цепочкой `main() → Player.jump() → Physics.impulse()` и точными строками.

- **Что стоит.** Граф кода строится локально через tree-sitter, 0 токенов. Дороже только `/graphify .` внутри Claude Code: он силами вашей модели разбирает документы и картинки. Запускайте его, когда в проекте появился геймдизайн или ТЗ.
- **Подводный камень.** Скилл graphify весит около 47 КБ и целиком попадает в контекст при вызове `/graphify`. В обычной работе он не нужен: Claude зовёт команды `graphify query`, `explain` и `path` напрямую.
- **Как держать свежим.** Git-хуки обновляют граф после каждого коммита, после `git pull` нужно выполнить `graphify update .`.
- **Качество.** Граф не заменяет чтение кода перед правкой, он подсказывает, какие строки читать. Часть связей помечена INFERRED (догадка парсера), в тесте их было 8%.

В наборе graphify ставится автоматически: CLI, скилл, хуки, первый граф и git-хуки. Агенты code-scout и Explore начинают поиск с графа.

## Со скриншотов

Ни один из пяти репозиториев не скилл для Claude Code, и бесплатных токенов Claude ни один не даёт. В набор я их не включил, но два пригодятся для самих игр.

| Репозиторий | Что это на самом деле | Брать? |
| --- | --- | --- |
| [freellmapi](https://github.com/tashfeenahmed/freellmapi) (\~40k ★, MIT) | Локальный роутер по бесплатным тарифам 34 провайдеров (Gemini, Groq, Llama, Qwen и др.) за одним API. Claude Code можно на него переключить, но тогда код пишет не Claude, а случайная бесплатная модель | **Для разработки нет.** Это прямой удар по качеству: модель меняется при каждом упоре в лимит, автор пишет «Personal experimentation only», а бесплатные тарифы часто обучаются на ваших данных. Подходит для прототипа ИИ внутри игры (диалоги NPC, генерация вопросов для викторины), если там нет данных отдела |
| public-apis | Каталог бесплатных API: викторины, погода, картинки, праздники | Да, как источник контента для игр. Устанавливать ничего не нужно |
| awesome-mcp-servers | Каталог MCP-серверов | Как справочник. Каждый MCP добавляет контекст, ставьте только под конкретную задачу (например, спрайты) |
| awesome-cursorrules | Правила для Cursor, не для Claude Code | Нет. Нужное оттуда уже покрывают правила Карпаты и наш CLAUDE.md |
| build-your-own-x | Учебники «напиши свой X», в том числе игровой движок | Для себя почитать. В окружение не нужен |

По-настоящему экономит токены другое: короткий контекст, тёплый кэш и Haiku на поиске. Всё это уже есть в наборе.

## Готовый набор для проекта

Всё из этого документа собрано в архив `game-kit.zip`. Скопируйте его в корень проекта и запустите `bash setup.sh`. Я прогнал скрипт на чистой машине: все 17 шагов установки прошли без ошибок. Шесть плагинов вместе добавляют около 1 300 токенов в каждую сессию (данные `claude plugin details`), самый тяжёлый — Superpowers, около 850.

| Часть | Что делает |
| --- | --- |
| `CLAUDE.md` | Правила работы, шаги проверки качества, инструкции для компакта |
| `PLAN.md` | Состояние работы между сессиями |
| `.claude/settings.json` | Sonnet + советник Opus, effort medium, компакт на 200K, хук фильтра вывода |
| `.claude/agents/` | log-reader, code-scout и Explore на Haiku |
| `.claude/skills/game-architecture/` | Шаблон описания игры |
| `setup.sh` | Superpowers, правила Карпаты, typescript-lsp, claude-md-management, code-simplifier, frontend-design, find-skills, webapp-testing, game-feel, game-engine, graphify (с первым графом и git-хуками). С флагом `--with-mem` ещё claude-mem на Gemini |
| `README.md` | Установка за 5 шагов и порядок работы на каждый день |

Одно уточнение к разделу «Свои субагенты»: встроенный Explore работает на основной модели, а не на Haiku. Поэтому в наборе он переопределён на Haiku. `model` во frontmatter агента важнее `CLAUDE_CODE_SUBAGENT_MODEL`, так что Haiku-агенты остаются на Haiku, а остальные субагенты работают на Sonnet.
