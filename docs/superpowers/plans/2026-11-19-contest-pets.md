# Доработка питомцев победителей конкурса (СР3, СР5, СР9) — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** новые листы «Рост» для СР3, СР5, СР9 с доработками на 3–5-й стадиях, нарезанные в `public/assets/pets/`, одобренные владельцем.

**Architecture:** Codex через мост правит готовый лист со всеми пятью стадиями (по образцу и картинкам руководителей), временный скрипт проверяет лист требованиями нарезки и собирает превью «было/стало», после одобрения `tools/slice-pets.py` нарезает лист. Код игры не меняется.

**Tech Stack:** `tools/agent-bridge/bridge.py` (Codex `image_gen`), Python (Pillow, numpy, scipy), `tools/slice-pets.py`.

**Spec:** `docs/superpowers/specs/2026-11-19-contest-pets-design.md`

## Global Constraints

- Работаем только в git-копии сессии `.claude/worktrees/epic-gould-65c718`.
- В основной копии разрешено одно: после одобрения писать в её `assets/_raw/`. Её `public/assets/pets/` (пляжные версии соседней сессии) не трогаем никогда.
- Листы до правки: `assets/_raw/srN-rost-pre-contest.png`. Имя `-old` занято.
- В git не кладём: `assets/_raw/`, `work/`, картинки руководителей.
- Коммиты только по явным путям. Без force-push. Реальные фамилии не печатаем.
- **Требования нарезки:**
  - прозрачный фон, ровно 5 фигур в ряд;
  - высота фигур слева направо строго растёт, вместе с предметами;
  - предметы касаются тела;
  - каждая нарезанная стадия не шире своей высоты.
- **Решения дизайна:**
  - СР9: два полных листа, А (красная шапка, чёрные туфли) и Б (без шапки, бежевые туфли);
  - СР3: розовая страйкбольная M4 с малиновыми деталями, наискось у груди, стволом вверх; надпись магазина с фото не переносится;
  - СР5: тёмно-коричневый символ на лбу; круглый полупрозрачный щит, светится зелёным, как меч, символ в центре, в свободной руке.
  - Доработки только на 3–5-й стадиях. 1–2-я без новых деталей.
- **Отказ Codex рисовать винтовку или символ** → вопрос владельцу, без повторов молча.

## Review Focus

- **Codex меняет лицо или пропорции персонажа**, особенно на 1–2-й стадии. Ожидание: персонаж узнаётся на всех стадиях. Проверка — глазами владельца по превью «было/стало».
- **Шрифт, водяной знак или подпись попали в картинку.** Ожидание: на листе только персонажи. Проверка — превью; лист с текстом не показываем.
- **Свечение щита СР5 после нарезки.** Скрипт перекрашивает светлую кайму у контура, и свечение может потемнеть или пропасть. Ожидание: щит выглядит, как на листе. Превью строится из нарезанных стадий, не из листа.
- **Повторная нарезка меняет СР1, СР2, СР6.** Ожидание: их файлы байт в байт прежние (`git status`, задача 4).
- **Пляжные версии СР3, СР5, СР9 устарели после выпуска.** Ожидание: владелец знает и передаёт это работе магазина (задача 4, итоговое сообщение).
