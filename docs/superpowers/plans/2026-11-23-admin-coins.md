# Ручная выдача монет РГ в админке — план

## Context

Группы меняли купленную мебель (стол на другой стол), а монеты за старую вещь сгорали: так задумано в магазине (`docs/superpowers/specs/2026-11-18-rg-shop-design.md`, «Замена»). Владелец хочет сам выдавать группе монеты из админки, чтобы до 30.11 группы могли дальше обставлять комнату. Дизайн согласован 23.11: `docs/superpowers/specs/2026-11-23-admin-coins-design.md` (коммит 791adf9).

Монеты нигде не хранятся: `shopState` (`src/engine/shop.ts:84`) считает `coins` из процента плана оплат и вычитает покупки (`balance = coins − spent`). Выдача — новая запись журнала правок (лист «Overrides») `kind: 'coins'`, `delta` = число монет (может быть с минусом), как «Выдать аптечку». Сервер (`apps-script/Code.gs:41`) сейчас принимает от админки только `piles`, `medkits`, `toys` с пределом ±20 — нужна новая версия `Code.gs` (v7).

Итог: во вкладке «Ручные правки» строка «Монеты» — «Сейчас» показывает остаток группы, «Выдать монеты» добавляет число из поля «Количество» (минус — забрать). Остаток на странице РГ растёт; стадии, рейтинги, кучки и порог отпуска не меняются.

## Решения исполнителя

- Вид правки — `'coins'` (понятно в листе таблицы). Чтобы не путать с `ShopState.coins` (заработано, 1% плана = 1 монета), выданное — новое поле `ShopState.granted`.
- Предел одной записи `coins` на сервере ±100 (`COINS_DELTA_MAX`), у остальных видов ±20 как было. Клиент шлёт выдачу монет одной записью (без `splitDelta`).
- Кнопки «Сбросить» у монет нет: ошибку гасит выдача с минусом.
- «Сейчас» у монет — `balance` как есть (может быть меньше нуля; страница РГ показывает 0), на выбранную в форме дату.

## Изменения

**1. Движок** (TDD: сначала тесты в `src/engine/shop.test.ts`)
- `src/engine/pet.ts:6-14`: `Override.kind` += `'coins'`, строка в комментарии. `applyOverrides` (`pet.ts:100`) неизвестные виды уже пропускает — тест, что `coins` не меняет `PetState`.
- `src/engine/shop.ts`: `ShopState.granted: number`; в цикле `shopState` сумма `delta` записей `coins` с `date ≤ asOf`; `balance = coins + granted − spent`. `coins` (заработано) не трогаем — `vacationBlock` (`src/rg/shop.ts:48`) сравнивает его с `VACATION_AT`.
- Тесты: выдача прибавляется к `balance`, не к `coins`; минус забирает; запись с датой после `asOf` не считается; выдача не включает отпуск; покупка тратит выданное.
- Литералы `ShopState`: `src/main.ts:57` (демо), `src/rg/main.ts:17` (`EMPTY_SHOP`) — `granted: 0`.
- `src/data/facts.test.ts` (рядом с тестами магазина ~534): снимок + запись `coins` +N → `states[g]` прежние (`planPercent`, `stage`, кучки, аптечки, игрушки), `shop[g].coins` прежний, `shop[g].balance` +N ровно, отпуск не открывается, даже если `coins + N ≥ VACATION_AT`. `facts.ts:176-180` отдаёт один и тот же список правок и `simulate`, и `shopState` — этот тест закрепляет «выдача не влияет на правила».
