# Магазин РГ — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** РГ покупает за монеты (1% плана = 1 монета) мебель для комнаты питомца. Мебель стоит в комнате на ТВ, питомец звонит по телефону, работает за компьютером, пьёт у кулера. При 100% плана группа уезжает в отпуск на пляж.

**Architecture:**
- Покупка и отпуск — новые записи журнала РГ (`kind: 'buy' | 'vacation'`) в листе «Overrides»; сервер только проверяет PIN, повтор `ref` и дневной предел.
- Чистый модуль `src/engine/shop.ts` пересчитывает из снимка монеты, траты, мебель по местам и отпуск. `buildFacts` отдаёт это рядом с состояниями питомцев.
- ТВ (`RoomView`, `PetActor`) и страница РГ берут магазин только из `facts.shop`.

**Tech Stack:** Vite + TypeScript, DOM/CSS/WAAPI, Vitest, Playwright (`check:render`, `check:admin`), Google Apps Script (`apps-script/Code.gs`), мост Codex для картинок (`tools/agent-bridge`).

**Spec:** `docs/superpowers/specs/2026-11-18-rg-shop-design.md`

## Global Constraints

- **Монеты.** `coins = floor(P × 10000 / gameCents)`:
  - `P` — все действующие оплаты группы с `startDate` по `asOf` включительно, все поколения;
  - без плана (`gameCents = 0`) — 0.
- **Покупки:**
  - при пересчёте засчитываются без проверки монет;
  - условия засчитывания: код известен; для `pc`/`phone` уже засчитан стол; вещь сейчас не стоит на своём месте;
  - `balance = coins − spent`, может быть < 0; на экране показывается `max(0, balance)`.
- **Отпуск:**
  - последняя запись `vacation` решает (1 — в отпуске, 0 — нет), процент при пересчёте не проверяется;
  - порог `VACATION_AT = 100` проверяет только страница РГ.
- **Коды и цены каталога** — таблица «Каталог» спеки, дословно. Коды 1–25 неизменны, цены после выпуска не меняются.
- **Сервер:**
  - `buy {item: 1..25, ref}`, `vacation {on: boolean, ref}`, PIN группы;
  - дата — сегодня сервера;
  - повтор `ref` той же группы ничего не пишет;
  - пределы в день на группу: 30 покупок, 10 отпусков;
  - монеты и процент сервер не проверяет.
- **Звонок:**
  - условия: телефон куплен; питомец жив, вылупился, стадия ≥ 2; не болен; не в отпуске; не в трюке; не удержан;
  - интервал случайный, 3–6 минут на комнату;
  - реплики ≤ 28 знаков, 2–4 на диалог, первая — клиента;
  - 8 диалогов спеки дословно.
- **Безопасность и репозиторий:**
  - PIN только в памяти; у поля PIN нет `name`; PIN не попадает в URL, `localStorage`, `sessionStorage`, консоль;
  - реальных ФИО и xlsx в репозитории нет;
  - новый ассет — строка в `CREDITS.md`;
  - проверки пишут только в мок (`npm run mock-backend`), не в живой бэкенд.
- **Git:**
  - в git только явными путями;
  - не коммитить `assets/_raw/`, `work/`, `.claude/settings.json`, `rooms-and-walk.html`, `graphify-out/2026-11-*/`, `.claude/worktrees/`, `.agents/`, `.codex/`, `AGENTS.md`;
  - трейлер коммита `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`;
  - ветка `tv-screen`; в `master` — только после «да» владельца.
- **Порядок работы:**
  - сначала `~/.local/bin/graphify.exe query`, после правок кода `graphify update .`;
  - сборка, тесты и логи — через субагент `log-reader`;
  - ревью — субагент `reviewer`.

## Review Focus

1. **Старый бэкенд и новый сайт.** Пока `Code.gs` не обновлён, «Купить» получает `bad_request`. Ожидание: понятная ошибка «Сервер не принял покупку», страница РГ дальше работает. Тест — задача 4, шаг 1 (`purchaseError`).
2. **Две вкладки РГ или устаревший снимок, покупка сверх монет.** Ожидание: покупка засчитана, баланс показан 0, все «Купить» серые с «Не хватает N», пока группа не отработает минус. Тесты — задача 1 (`balance < 0`) и задача 4 (`shopCards` при отрицательном балансе).
3. **Перехват звонка.** Звонок обрывают прогулка, «итоги дня», скрытая вкладка или новая игрушка дня. Ожидание: в комнате не остаётся облачков клиента, дрожи телефона и `data-call`, питомец свободен. Тест — задача 7, шаг 6 (`check:render`, перехват).
4. **Мебель против интерфейса комнаты в каждой из шести тем**, при 5 кучках и непустых ящиках. Ожидание: ничего не перекрывает табличку, табло, ящики, кучки. Тест — задача 6, шаг 1 (`furniture.test.ts`, все темы) и шаг 7 (замер DOM в `check:render`).
5. **Компьютер или телефон, купленный до стола** (две вкладки, повтор). Ожидание: не засчитан, монеты не потрачены; после покупки стола повторить можно. Тест — задача 1 (`компьютер без стола`).
