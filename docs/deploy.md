# Выпуск игры: Apps Script, PIN, GitHub Pages

Для человека, который запускает игру. Что делает Claude, а что вы, разделено по шагам. Игра идёт со 2 по 22 ноября 2026.

Сайт: `https://konturproject.github.io/sales-pets/`

| Страница | Адрес |
|---|---|
| общий экран | `…/sales-pets/` |
| страница руководителя группы | `…/sales-pets/rg.html` |
| админка | `…/sales-pets/admin.html` |

## Правила про PIN

- PIN не отправляйте в чат, почту и мессенджеры, не вставляйте в адрес страницы, не записывайте в репозиторий и в таблицу.
- PIN групп передавайте руководителям лично (на словах или на бумаге) и по одному.
- Админ-PIN вводите только вы. Claude PIN не вводит и не просит.
- Пять неверных PIN подряд блокируют вход на 10 минут (отдельно для админа и для каждой группы). Если заблокировали сами: подождите 10 минут.

## 1. Бэкенд: Google Apps Script (вы, ≈ 20 минут, один раз)

Подробные шаги и список действий: [`apps-script/README.md`](../apps-script/README.md). Коротко и с ловушками:

1. Создайте пустую Google-таблицу. Идентификатор — часть адреса между `/d/` и `/edit`.
2. В таблице: **Расширения → Apps Script**. Вставьте содержимое `apps-script/Code.gs`. В **Настройки проекта** включите «Показывать файл манифеста» и вставьте `apps-script/appsscript.json`.
3. **Настройки проекта → Свойства скрипта**: `SPREADSHEET_ID` (идентификатор из шага 1) и `INITIAL_PIN` (ваш первый админ-PIN, 4–12 цифр; придумайте свой, не `1234`).
4. Запустите функцию `setupSpreadsheet`, затем `initAdminPin`. Google попросит разрешения для скрипта: разрешите. После `initAdminPin` свойство `INITIAL_PIN` стирается само, остаётся только хеш.
5. **Развернуть → Новое развёртывание → Веб-приложение**: «Выполнять от имени» — **я**, «У кого есть доступ» — **все** (не «все в организации»: страницы читают данные без входа в Google).
6. Скопируйте адрес, который заканчивается на `/exec`.

**Пришлите Claude только этот адрес `…/exec`.** Он не секрет: все равно виден в коде страницы. PIN не присылайте.

Ловушки:
- Правки `Code.gs` после развёртывания не действуют, пока не выпущена новая версия: **Развернуть → Управлять развёртываниями → карандаш → Версия: Новая версия → Развернуть**. Адрес `/exec` при этом остаётся прежним. «Новое развёртывание» даёт новый адрес, и его придётся менять на сайте (шаг 2).
- Админ-PIN меняется в админке: вкладка **PIN-коды** → «Админ-PIN» (новый PIN дважды; совпадать с PIN группы нельзя). Старый перестаёт работать сразу.

## 2. Сайт: GitHub Pages (Claude)

Сайт собирается и выкладывается GitHub Actions при каждом пуше в `master` (`.github/workflows/pages.yml`: проверка типов, тесты, сборка). Адрес бэкенда подставляется в сборку из переменной репозитория `BACKEND_URL`.

После получения вашего адреса `…/exec` Claude:
1. записывает его в переменную `BACKEND_URL`, перезапускает сборку и ждёт выкладки;
2. запускает `node tools/smoke-live.mjs <адрес>`: GET снимка, опрос «без изменений», неизвестное действие (входов в систему нет, попытки PIN не тратятся);
3. открывает сайт в браузере и проверяет, что экран получает данные с github.io.

Если `BACKEND_URL` пуста, сайт собирается, но показывает «Игра ещё не запущена».

Открытые страницы сами узнают о новой сборке (номер в `version.json`): экран ТВ перезагружается сам, в админке и на странице РГ появляется плашка «Вышла новая версия — обновите страницу». Нажимать F5 на ТВ после выпуска не нужно.

Сделать то же самое самому:
```bash
gh variable set BACKEND_URL --body "https://script.google.com/macros/s/…/exec"
gh workflow run pages.yml
node tools/smoke-live.mjs "https://script.google.com/macros/s/…/exec"
```

## 3. PIN групп (вы)

1. Откройте `…/sales-pets/admin.html`, введите админ-PIN.
2. Вкладка **PIN-коды** → «Выпустить PIN групп» → «Да, выпустить». PIN шести групп показываются **один раз**; повторный выпуск обнуляет старые.
3. Передайте каждому руководителю PIN его группы лично, потом закройте окно кнопкой «Закрыть» (кнопка «Копировать» кладёт PIN в буфер обмена: не вставляйте его в чат).
4. Руководитель открывает `…/sales-pets/rg.html`, выбирает группу, вводит PIN.

## 4. Данные (вы, в админке)

Над вкладками админки — блок **«Сегодня»**: день игры, по какой день загружены воронка и оплаты, сколько групп внесли предварительные числа, и под ним дела дня. Зелёные ✓ сделаны, янтарные → ждут вас: «Загрузите воронку за 02.11 (Импорт)», «Новички без даты приёма: 3» и т. п. Сверяйтесь с ним каждое утро: когда янтарных нет, на сегодня всё загружено.

**02.11, первый день игры.**
1. **PIN-коды** — раздел 3.
2. **Импорт → воронка**: ноябрьский отчёт `АП_НП_СР_Воронка_Дни…` (если в нём ещё нет строк сотрудников — октябрьский, но тогда уволенным в октябре сразу поставьте дату увольнения: иначе их пустая норма ляжет на группу). В первый день админка берёт из отчёта **только штат** (так только 02.11; с 03.11 файл без дней игры отклоняется): превью покажет «Первая загрузка», сколько сотрудников в файле, сколько новых по группам и их ФИО; кнопка «Добавить в штат (N)». Показатели воронки из этого файла не загружаются. Все добавятся уровнем «опытный» без даты приёма. Группа сотрудника берётся из файла; оплаты потом привязываются к нему по ФИО (на октябрьских файлах совпали все авторы оплат).
3. **Сотрудники → «Уровни и даты приёма»**: новичкам уровень («Новичок 1» — первая неделя, «Новичок 2» — вторая) и дату приёма, одна кнопка «Сохранить изменения». Кто уже уволен, но есть в отчёте, — дата увольнения в его карточке. Сохраните таблицу до того, как сохранять карточку сотрудника или грузить JSON: эти записи перерисовывают таблицу, и несохранённые правки в ней пропадут.
   Запасной путь — **Сотрудники → «Загрузить список из JSON»**: `[{"name": "Фамилия Имя Отчество", "group": "СР1", "baseLevel": "rookie1", "hireDate": "2026-10-28"}, …]`; уровни `experienced`, `rookie1`, `rookie2`. ФИО — точно как в отчёте воронки (ё и е не различаются). Файл не кладите в репозиторий.
4. **Нормы и пороги → «Личные нормы по уровням»**: у каждого уровня поле **«оплат в день»** — личный план оплат сотрудника на рабочий день, можно дробно (`0,4` — это 2 оплаты в неделю). Сейчас стоят заглушки: опытный 0,4, новичок 1 — 0, новичок 2 — 0,2; поставьте свои. План группы на игру = сумма личных планов по рабочим дням; стадии 2–5 наступают при 25 / 50 / 75 / 100 % этого плана (пороги правятся там же). Сытость за день — от плана группы на этот день. Перед записью превью покажет, у каких групп сегодня сменится стадия. Правку можно сделать «с даты».
5. **Оплаты** в течение дня: предварительные числа оплат по группам — питомцы на экране реагируют сразу. Карточка группы в её цвете, кнопки − и + меняют число на одну оплату (удобно с телефона); изменённые карточки подсвечены, пока не нажмёте «Сохранить».

**С 03.11 каждое утро** (до 11:00, данные по последний рабочий день; после выходных и 04.11 админка подставит его сама):
1. **Импорт → воронка**: свежий отчёт `АП_НП_СР_Воронка_Дни…`, скачанный этим утром (не вчерашний файл для штата). Если за вчера у всех нули, превью предупредит: скачайте отчёт заново. Если в нём есть сотрудник, которого не было в списке, он появится в штате как «опытный» без даты приёма — сразу поправьте его в таблице **Сотрудники → «Уровни и даты приёма»**: пока уровень не исправлен, его день оценён нормой опытного (у группы лишняя кучка, после правки пересчитается).
2. **Импорт → оплаты**: выгрузка «Детальные данные по оплаченным счетам». Повторная загрузка того же периода заменяет его, а не удваивает; предварительные числа за эти дни заменяются файлом. В превью — счета по группам и «Авторы не найдены в штате»: их оплаты кормят питомца, но не идут в рейтинг — проверьте написание ФИО в штате (или добавьте сотрудника) и загрузите файл ещё раз.
3. Отпуска и больничные: вкладка **Сотрудники**.

**Разбор загрузки и «Итоги».** До кнопки «Загрузить» превью воронки показывает таблицу «Итогов» за загружаемый день так, будто файл уже загружен: план/факт качественных, длинных и оплат по группам (раскрываются в сотрудников), «Итог дня» (аптечка, кучка, игрушка) и «Сейчас станет» — что изменится у питомцев. Если у сотрудника явно не те числа (счёт или звонок не попал в выгрузку CRM), кнопка «Поправить» у его строки записывает ручную правку факта за этот день, и разбор пересчитывается. Вкладка **Итоги** (первая) показывает то же за любой прошедший день; внизу «Ручные правки фактов» — список всех правок с «Отменить». Правка хранится отдельно от файлов: повторная загрузка её не стирает.

**Что видят на ТВ.** После загрузки воронки экран ТВ один раз показывает событие «итоги дня»: камера по очереди подъезжает к комнатам, где что-то изменилось (по 7 с, всё не дольше 45 с), плашка пишет, за что («СР3 · итоги 05.11: длинные 2 из 4 — кучка; качественные 7 из 6 — игрушка»), питомец тужится и появляется кучка, убранная кучка исчезает облачком, аптечка или игрушка падает в ящик. ТВ, включённый позже утром, покажет итоги при запуске; повторно (F5, новая сборка) — нет. Расход РГ на ТВ: аптечка — красный плюс над питомцем, игрушка падает в комнату, и до конца дня питомец играет с ней вместо мяча. Прогулка — раз в 5 минут (камера четыре раза проходит комнаты и доски, потом 80 с в зале): выход из комнат, встречи, визит к больному, «кусь»/«догоню!», догонялки по кругу и в случайном порядке мяч с беготнёй, паровозик («ту-ту!») и чехарда; оставшееся время питомцы бродят по залу. Больной в играх не бегает — смотрит у края зала. Выбор игр и порядок — только анимация, на игру и рейтинги не влияют.

**Выходные дни.** **Нормы и пороги → «Выходные дни»**: нажатие на день делает его выходным или рабочим, «Сохранить» показывает последствия (итоги каких дней и питомцы сегодня изменятся), «Применить» записывает. Выходной не оценивается, его оплаты идут в следующий рабочий день, план оплат считается без него.

Файлы xlsx не кладите в репозиторий: они в `.gitignore`, и `npm run audit:publish` проверяет, что фамилий из них нет в коде и истории.

## 5. Если что-то не так

| Что видите | Что делать |
|---|---|
| «Игра ещё не запущена…» | `BACKEND_URL` пуста. Задайте переменную и перезапустите `pages.yml` (раздел 2) |
| «Нет связи с сервером» на экране | Адрес бэкенда неверен, или «Доступ» развёртывания не «все», или Apps Script упал. Откройте `…/exec` в браузере: должен быть JSON, а не страница входа Google. Затем `node tools/smoke-live.mjs <адрес>` |
| Вход: «locked» | Пять неверных PIN подряд: подождите 10 минут |
| Вход: «Неверный PIN» у руководителя | Выпустите PIN группы заново (раздел 3), прежние перестанут работать |
| Данные в таблице правили руками, а страница старая | Запустите функцию `bumpVersion` в Apps Script: страницы перечитывают данные только при росте версии |
| ТВ не показал «итоги дня» | Итоги показываются один раз на ТВ: при загрузке воронки, если экран открыт, или при запуске экрана в следующий рабочий день после загруженного. Воронку, загруженную в выходной, ТВ покажет, только если его перезапустить в следующий рабочий день. Сами итоги всегда видны во вкладке **Итоги** |
| У группы кучка или нет игрушки, а сотрудники уверены, что норму сделали | **Итоги** → день → группа → сотрудники: сверьте факт с CRM; если число неверное, «Поправить» у сотрудника — итог дня и питомец пересчитаются |
| Снимок отвечает долго (> 3 с) | `smoke-live` выдаст предупреждение; тогда Claude добавит кэш частями |

## 6. Откат

- **Сайт**: нужная версия лежит в истории git. `git revert <коммит>` и пуш в `master` выкладывают прежний вид; либо откройте Actions → Pages → прежний успешный запуск → Re-run all jobs.
- **Бэкенд**: Apps Script → **Управлять развёртываниями** → карандаш → выберите прежнюю версию → Развернуть. Данные в таблице при этом не откатываются.
