# Выпуск игры: Apps Script, PIN, GitHub Pages

Для человека, который запускает игру. Что делает Claude, а что вы, разделено по шагам. Игра идёт со 2 по 22 ноября 2026.

Сайт: `https://konturproject.github.io/sales-pets/`

| Страница | Адрес |
|---|---|
| общий экран | `…/sales-pets/` |
| страница руководителя группы | `…/sales-pets/rg.html` |
| админка | `…/sales-pets/admin.html` |

## Правила про PIN

- PIN не отправляйте в чат, почту и мессенджеры, не вставляйте в адрес страницы, не записывайте в репозиторий и в таблицу.
- PIN групп передавайте руководителям лично (на словах или на бумаге) и по одному.
- Админ-PIN вводите только вы. Claude PIN не вводит и не просит.
- Пять неверных PIN подряд блокируют вход на 10 минут (отдельно для админа и для каждой группы). Если заблокировали сами: подождите 10 минут.

## 1. Бэкенд: Google Apps Script (вы, ≈ 20 минут, один раз)

Подробные шаги и список действий: [`apps-script/README.md`](../apps-script/README.md). Коротко и с ловушками:

1. Создайте пустую Google-таблицу. Идентификатор — часть адреса между `/d/` и `/edit`.
2. В таблице: **Расширения → Apps Script**. Вставьте содержимое `apps-script/Code.gs`. В **Настройки проекта** включите «Показывать файл манифеста» и вставьте `apps-script/appsscript.json`.
3. **Настройки проекта → Свойства скрипта**: `SPREADSHEET_ID` (идентификатор из шага 1) и `INITIAL_PIN` (ваш первый админ-PIN, 4–12 цифр; придумайте свой, не `1234`).
4. Запустите функцию `setupSpreadsheet`, затем `initAdminPin`. Google попросит разрешения для скрипта: разрешите. После `initAdminPin` свойство `INITIAL_PIN` стирается само, остаётся только хеш.
5. **Развернуть → Новое развёртывание → Веб-приложение**: «Выполнять от имени» — **я**, «У кого есть доступ» — **все** (не «все в организации»: страницы читают данные без входа в Google).
6. Скопируйте адрес, который заканчивается на `/exec`.

**Пришлите Claude только этот адрес `…/exec`.** Он не секрет: все равно виден в коде страницы. PIN не присылайте.

Ловушки:
- Правки `Code.gs` после развёртывания не действуют, пока не выпущена новая версия: **Развернуть → Управлять развёртываниями → карандаш → Версия: Новая версия → Развернуть**. Адрес `/exec` при этом остаётся прежним. «Новое развёртывание» даёт новый адрес, и его придётся менять на сайте (шаг 2).
- Админ-PIN сменить из админки нельзя (кнопки нет), только запросом `changePin` из `apps-script/README.md`. Придумайте PIN сразу такой, какой оставите.

## 2. Сайт: GitHub Pages (Claude)

Сайт собирается и выкладывается GitHub Actions при каждом пуше в `master` (`.github/workflows/pages.yml`: проверка типов, тесты, сборка). Адрес бэкенда подставляется в сборку из переменной репозитория `BACKEND_URL`.

После получения вашего адреса `…/exec` Claude:
1. записывает его в переменную `BACKEND_URL`, перезапускает сборку и ждёт выкладки;
2. запускает `node tools/smoke-live.mjs <адрес>`: GET снимка, опрос «без изменений», неизвестное действие (входов в систему нет, попытки PIN не тратятся);
3. открывает сайт в браузере и проверяет, что экран получает данные с github.io.

Если `BACKEND_URL` пуста, сайт собирается, но показывает «Игра ещё не запущена».

Сделать то же самое самому:
```bash
gh variable set BACKEND_URL --body "https://script.google.com/macros/s/…/exec"
gh workflow run pages.yml
node tools/smoke-live.mjs "https://script.google.com/macros/s/…/exec"
```

## 3. PIN групп (вы)

1. Откройте `…/sales-pets/admin.html`, введите админ-PIN.
2. Вкладка **PIN-коды** → «Выпустить PIN групп» → «Да, выпустить». PIN шести групп показываются **один раз**; повторный выпуск обнуляет старые.
3. Передайте каждому руководителю PIN его группы лично, потом закройте окно кнопкой «Закрыть» (кнопка «Копировать» кладёт PIN в буфер обмена: не вставляйте его в чат).
4. Руководитель открывает `…/sales-pets/rg.html`, выбирает группу, вводит PIN.

## 4. Данные (вы, в админке)

Порядок первого запуска:
1. **Импорт → воронка**: загрузите отчёт воронки (файл `АП_НП_СР_Воронка_Дни…`). Новые сотрудники появятся в штате.
2. **Сотрудники**: у каждого нового проверьте группу, уровень (Опытный, Новичок 1 или Новичок 2) и дату приёма. От них зависят нормы.
3. **Импорт → оплаты**: загрузите выгрузку «Детальные данные по оплаченным счетам». Повторная загрузка того же периода заменяет его, а не удваивает.
4. **Нормы и пороги**: дневная норма оплат группы (среднее прошлого месяца), нормы новичков и пороги стадий роста, когда заказчик их назовёт. Правку можно сделать «с даты».
5. Отпуска и больничные: вкладка **Сотрудники**.

Файлы xlsx не кладите в репозиторий: они в `.gitignore`, и `npm run audit:publish` проверяет, что фамилий из них нет в коде и истории.

## 5. Если что-то не так

| Что видите | Что делать |
|---|---|
| «Игра ещё не запущена…» | `BACKEND_URL` пуста. Задайте переменную и перезапустите `pages.yml` (раздел 2) |
| «Нет связи с сервером» на экране | Адрес бэкенда неверен, или «Доступ» развёртывания не «все», или Apps Script упал. Откройте `…/exec` в браузере: должен быть JSON, а не страница входа Google. Затем `node tools/smoke-live.mjs <адрес>` |
| Вход: «locked» | Пять неверных PIN подряд: подождите 10 минут |
| Вход: «Неверный PIN» у руководителя | Выпустите PIN группы заново (раздел 3), прежние перестанут работать |
| Данные в таблице правили руками, а страница старая | Запустите функцию `bumpVersion` в Apps Script: страницы перечитывают данные только при росте версии |
| Снимок отвечает долго (> 3 с) | `smoke-live` выдаст предупреждение; тогда Claude добавит кэш частями |

## 6. Откат

- **Сайт**: нужная версия лежит в истории git. `git revert <коммит>` и пуш в `master` выкладывают прежний вид; либо откройте Actions → Pages → прежний успешный запуск → Re-run all jobs.
- **Бэкенд**: Apps Script → **Управлять развёртываниями** → карандаш → выберите прежнюю версию → Развернуть. Данные в таблице при этом не откатываются.
