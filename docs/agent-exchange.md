# Протокол обмена ассетами

Протокол первой версии связывает Claude Code и Codex через файлы одного проекта. Claude — ведущий: формулирует задачу, запускает мост и интегрирует результат. Codex — исполнитель генерации, работающий в каталоге одного задания. Общие файлы позволяют позже сменить интерфейс, сохранив задания и ассеты; истории чатов остаются раздельными.

## Задание

Вход — JSON в UTF-8 с двумя обязательными строками `id` и `prompt`. Необязательный массив `references` позволяет передать поддерживаемые мостом локальные референсы:

```json
{
  "id": "forest-slime-001",
  "prompt": "Создай оригинального лесного слизня для платформера: вид сбоку, прозрачный фон, полный силуэт. Используй только встроенный image_gen, сохрани PNG и manifest.json."
}
```

`id` уникален в проекте и используется как имя каталога задания: от 1 до 64 символов, строчные латинские буквы, цифры, дефис и подчёркивание; первый символ — буква или цифра. Для исправления создавайте новый `id`, например `forest-slime-002`. Повторное использование существующего каталога запрещено.

В `prompt` передавайте цель и только существенные ограничения: вид персонажа, стиль, фон, позу, размер, требования к сетке кадров и совместимости с игрой. Указывайте точные параметры вместо предположений. `references` — массив строк с относительными путями существующих файлов внутри корня проекта. Файлы нужно перечислять явно; вложения из истории другого чата автоматически не передаются.

## Выполнение

Мост создаёт рабочий каталог:

```text
<project>/work/agent-exchange/jobs/<id>/workspace/
```

Перед каждым заданием мост выполняет `codex login status` и требует подтверждения `Logged in using ChatGPT`. Без него запрос останавливается до запуска модели. Поле `authentication_route` в выводе `doctor` показывает обнаруженный маршрут входа.

В окружение дочернего процесса не передаются `CODEX_API_KEY` и `OPENAI_API_KEY`. Это не изменяет окружение родительского процесса или сохранённую авторизацию Codex.

Codex получает задание через stdin. Базовый вызов:

```text
codex --ask-for-approval never exec --sandbox workspace-write --json --cd <workspace> --output-last-message <job>/result.txt -
```

`never` исключает интерактивное ожидание подтверждения; это не разрешение обходить ограничения. Если действие невозможно в доступных условиях, исполнитель сообщает блокировку. Скрипт сохраняет `request.json`, `status.json`, `events.jsonl`, `stderr.log` и `result.txt` внутри каталога задания для диагностики.

Исполнитель использует только нативный `image_gen`. При отсутствии инструмента, проблеме входа, запрете действия или исчерпании лимита он останавливается. Запрещены автоматический переход на Images API, поиск API-ключей и подмена генерации программно нарисованной картинкой.

PNG и `manifest.json` записываются внутри `workspace`. Исполнитель не интегрирует файлы в игровые каталоги. Каталог задания отделён от исходников для предотвращения конфликтов; он не является отдельной системой безопасности сверх стандартной песочницы Codex.

## Результат

Рабочий каталог содержит PNG и `manifest.json`, например:

```json
{
  "status": "ready",
  "assets": [
    {
      "path": "assets/forest-slime.png",
      "width": 1024,
      "height": 1024
    }
  ],
  "notes": "Один персонаж, вид сбоку. Перед импортом проверить прозрачность и масштаб в игре."
}
```

Manifest объявляет `status`: `ready` либо `blocked`. Для каждого готового ассета обязательны `path`, `width`, `height`. Путь относителен к `workspace`, указывает на существующий PNG и не выходит за пределы каталога, в том числе через ссылки. Размеры — фактические размеры файла. Не объявляйте желаемые размеры фактическими.

При блокировке исполнитель сохраняет, например:

```json
{
  "status": "blocked",
  "assets": [],
  "reason": "Встроенный image_gen недоступен в этой сессии.",
  "notes": "Запасной API не использовался."
}
```

Необязательное поле `frames` служит метаданными анимации. Оно не заменяет проверку сетки, порядка кадров и совместимости с импортёром игры. В `notes` сохраняйте полезные замечания: фон, рекомендуемый масштаб, ограничения результата. Прозрачность и качество анимации не считаются проверенными только по наличию этих полей.

## Состояния

| Состояние | Что делать ведущему |
| --- | --- |
| `running` | Дождаться завершения; не импортировать частично записанные файлы. |
| `ready` | Прочитать manifest и проверить результат перед интеграцией. |
| `blocked` | Исполнитель завершил запрос и объявил препятствие в manifest; сообщить причину, не включать платный запасной путь. |
| `failed` | Прочитать диагностику; для новой попытки создать задание с новым `id`. |

Состояние считывается командой:

```powershell
python tools/agent-bridge/bridge.py status --project . --job forest-slime-001
```

Мост выставляет `ready` после успешного завершения процесса и соответствующего события успеха, проверки manifest, существования перечисленных файлов внутри `workspace`, структуры PNG, CRC блоков и совпадения размеров из IHDR. Один удачный exit code или фраза исполнителя «готово» недостаточны. Проверка не декодирует все пиксели, не доказывает использование `image_gen` и не оценивает художественное качество, прозрачность каждого пикселя или плавность анимации. Подтверждение всей цепочки требует первого живого теста.

Если процесс не завершился успешно, в том числе из-за входа или ошибки сервиса, состояние — `failed`, даже если причиной было ограничение доступа. `blocked` требует корректного manifest и успешного завершения запроса. По умолчанию время задания ограничено 900 секундами; для обоснованно долгой генерации команда `run` принимает `--timeout` в секундах. Мост не повторяет запрос автоматически.

## Интеграция и смена интерфейса

Ведущий читает действующие инструкции проекта, забирает только `ready`-результат и переносит нужные файлы в принятые игровые каталоги. Подключение к сцене, импорт в движок, масштабирование и проверка сборки — отдельная часть его задачи.

Один файл изменяет один ведущий агент. Перед сменой Claude на Codex или обратно завершите текущую интеграцию и оставьте короткую запись: ID задания, статус, использованные пути и следующий шаг. Следующий агент читает эту запись и manifest. Общая папка не переносит скрытый контекст, память или авторизацию между продуктами и не запускает агентов сама по себе.
