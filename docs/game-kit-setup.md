# Game kit для Claude Code

Готовое окружение для проекта игры. Модель тратит меньше лимита, а качество не проседает: Opus думает над планом и сложными местами, Sonnet пишет код по плану, Haiku только ищет и читает.

## Установка (5 минут)

Нужны `claude`, `node` (для `npx`), `jq` и `uv` или `pipx` (для graphify, Python 3.10+). Если `uv` нет: `curl -LsSf https://astral.sh/uv/install.sh | sh`.

1. Скопируйте содержимое этой папки в корень проекта игры. Свой `CLAUDE.md`, если он уже есть, не затирайте: допишите в него разделы из нашего.
2. В корне проекта запустите:
   ```bash
   bash setup.sh              # основной набор
   bash setup.sh --with-mem   # то же плюс claude-mem
   ```
3. Перезапустите Claude Code и проверьте: `/plugin` → Installed, `/hooks` → PreToolUse (три хука: фильтр тестов и два хука graphify), `/agents`, папка `graphify-out/`.
4. Заполните заглушки `<...>` в `CLAUDE.md`. Потом попросите Claude: «Изучи проект и коротко заполни `.claude/skills/game-architecture/SKILL.md` по шаблону».
5. Закоммитьте `.claude/`, `CLAUDE.md` и `PLAN.md`. Если в проекте работает кто-то ещё, ему нужно один раз запустить `bash setup.sh`.

## Что внутри

| Файл | Зачем |
|---|---|
| `CLAUDE.md` | Правила работы (по мотивам правил Карпаты), шаги проверки качества, инструкции для компакта. Короткий, потому что он едет в каждом запросе |
| `PLAN.md` | Состояние работы. Claude обновляет его перед `/clear`, и новая сессия начинает с него, а не с длинной истории |
| `.claude/settings.json` | В этом проекте с 28.10.2026: Opus 5.5 основной, effort `high`, `ultracode`, компакт на 400K, субагенты по умолчанию и советник на Opus 5.5, хук фильтра вывода. Исходный набор был экономнее: Sonnet + советник Opus, effort `medium`, компакт на 200K |
| `.claude/hooks/filter-test-output.sh` | Тесты и сборка: при успехе 5 строк итога, при ошибке только ошибки. Код выхода сохраняется |
| `.claude/agents/log-reader.md` | Haiku: прогоняет сборку и тесты и возвращает только ошибки |
| `.claude/agents/code-scout.md` | Haiku: ищет, где что лежит в коде |
| `.claude/agents/Explore.md` | Подменяет встроенный Explore на Haiku. По умолчанию он работает на основной модели |
| `.claude/agents/reviewer.md` | Opus 5.5, effort `xhigh`: проверяет дифф или ветку, ничего не меняет, возвращает находки с файлом и строкой |
| `.claude/skills/game-architecture/` | Описание устройства игры (заполнено для этого проекта), чтобы Claude не изучал проект заново в каждой сессии |
| `setup.sh` | Ставит плагины и скиллы ниже |

## Важно про graphify

- Граф кода строится локально через tree-sitter: без LLM и без расхода лимита. Так его строит и `setup.sh`, и git-хуки после каждого коммита.
- Команда `/graphify .` внутри Claude Code дополнительно разбирает документы, PDF и картинки. Это делает модель вашей сессии, то есть за счёт лимита. Запускайте её, только когда в проекте появились важные документы (ТЗ, геймдизайн).
- Сам скилл graphify большой, около 47 КБ, и загружается целиком при вызове `/graphify`. Для обычной работы он не нужен: правила в CLAUDE.md заставляют Claude вызывать дешёвые команды `graphify query`, `explain` и `path` напрямую.
- Хуки graphify перед поиском и чтением файлов подсказывают Claude сначала спросить граф. Жёсткий режим, который запрещает читать файлы до запроса к графу: `GRAPHIFY_HOOK_STRICT=1`.
- После `git pull` выполните `graphify update .`. Посмотреть граф глазами можно в `graphify-out/graph.html`.
- `setup.sh` оставляет резервную копию `.claude/settings.json.graphify-bak`, её можно удалить.

## Важно про claude-mem

- По умолчанию claude-mem сжимает записи через Claude, то есть из вашего лимита. Поэтому `setup.sh` ставит его с провайдером Gemini: понадобится бесплатный ключ из Google AI Studio. Учтите, что на бесплатном тарифе Google может использовать данные для обучения. Если в коде есть данные отдела, лучше `MEM_PROVIDER=claude`.
- В начале каждой сессии claude-mem подмешивает в контекст выжимку прошлых сессий. Это токены в каждом запросе. Если память не нужна, хватит встроенной памяти Claude Code и `PLAN.md`.
- Телеметрию `setup.sh` выключает.

## Как работать каждый день

1. Новая механика: plan mode (Shift+Tab) → план → «выполняй план» → тесты.
2. Одна задача = одна сессия. В конце: «обнови PLAN.md», потом `/clear`.
3. Модель и effort меняйте в начале сессии, а не посередине, иначе сбросится кэш.
4. Перед сдачей игры отделу: субагент `reviewer`, `/code-review` или «попроси советника проверить».
5. Раз в неделю смотрите `/usage`: что съедает лимит.
