# Blender: модели и спрайты

## Главное правило экономии

Тяжёлую и повторяемую работу делают скрипты из `tools/blender/` через CLI, а не MCP-вызовы по шагам.
`run.sh` запускает Blender без интерфейса и возвращает только короткий JSON. Логи Blender в контекст не попадают.

| Задача | Как делать |
|---|---|
| Проверить модель | `bash tools/blender/run.sh check_asset.py <модель> --height <м>` |
| Привести к стандарту и экспортировать | `bash tools/blender/run.sh prepare_glb.py <модель или work/x.blend> --out assets/models/x.glb --height <м>` |
| Спрайт-листы из 3D | `bash tools/blender/run.sh render_sprites.py assets/models/x.glb --out assets/sprites/x [--directions 8 --frames 8 --size 128 --elevation 30 --anims Walk,Idle --pixel]` |
| Сжать GLB для веба | `npx -y @gltf-transform/cli optimize in.glb out.glb --compress meshopt --texture-compress webp` |
| Посмотреть состав GLB | `npx -y @gltf-transform/cli inspect x.glb` (текст, без картинок) |

Blender MCP (интерактивная сцена) — только когда нужно что-то **собрать или поправить руками в сцене**: расставить объекты, поправить материал, импортировать с Poly Haven, повернуть кость.

## Порядок работы с MCP (сервер mcp-for-blender)

1. Перед началом: Blender открыт, в панели N → MCP for Blender нажато Start MCP Server. Если инструменты не отвечают (`get_addon_status`), попроси пользователя запустить сервер, не повторяй вызов в цикле.
2. Состояние сцены — текстом через `get_scene_info` (объекты, размеры, здоровье мешей и ригов). Не вызывай его после каждого шага.
3. Изменения — небольшими `execute_blender_code`. Один шаг = один вызов, печатай только короткий итог. Большие скрипты падают по таймауту.
4. Картинки (`look`, `viewport_capture`) остаются в контексте и дорого стоят. Проверяй числами, а `look` вызывай максимум один раз в конце, с `max_size` 512 и режимом `angles`, чтобы увидеть модель с нескольких сторон одной картинкой.
5. Ассеты в сцену: `search_assets` → `import_asset` (Poly Haven, Poly Pizza, Sketchfab). Не скачивай вручную то, что есть там.
6. `generate_3d` (Meshy, Hyper3D, Hunyuan3D) тратит деньги или месячные генерации пользователя — только по явной просьбе.
7. Перед рискованным шагом и после каждого удачного этапа сохраняй файл: `bpy.ops.wm.save_as_mainfile(filepath="<abs>/work/<имя>.blend")`.
8. Скрипт из `tools/blender` внутри MCP-сцены:
   ```python
   import runpy, sys
   sys.argv = ["blender", "--", "--height", "1.8"]
   runpy.run_path("/abs/path/tools/blender/check_asset.py", run_name="__main__")
   ```
   Пути только абсолютные: у Blender своя рабочая папка. `render_sprites.py` через MCP не запускай, только через `run.sh`.
9. Одна сессия = один ассет. Готово → обнови `PLAN.md` → `/clear`.

## Не делай в Blender с нуля то, что можно взять

Свободное моделирование «из кубиков» через код — слабое место: долго, дорого, результат хуже готовых ассетов.
Порядок: готовая модель из библиотеки (скилл `game-assets`) → сгенерированная (Meshy/Tripo/Hi3D/Hunyuan3D) → и только потом моделирование в Blender. В Blender — сборка, доработка, риг, анимация, экспорт, рендер.

## Стандарт готовой модели (проверяет check_asset.py)

- Формат `.glb`, один файл: меш, материалы, текстуры, анимации.
- 1 единица = 1 метр. Персонаж 1.6–1.9 м (или как принято в проекте), предметы — в реальном размере.
- Точка опоры внизу по центру, в (0,0,0). Трансформации применены: масштаб 1, поворот 0.
- Лицом к −Y в Blender (это +Z в glTF и Three.js). Иначе `render_sprites.py --rotate 180` или поправить модель.
- Нормали наружу, без перевёрнутых граней. Без лишних висящих вершин.
- Бюджет треугольников для веб-игры: персонаж 3–15 тыс., предмет 0.3–5 тыс., фон 0.1–1 тыс.
- Материалы только Principled BSDF + картинки. Процедурные текстуры (Noise, Voronoi и т.д.) в glTF теряются — запекать.
- Текстуры до 2048 (для веба 1024), лучше степени двойки, упакованы в GLB.
- Риг: одна арматура, меш её дочерний объект. Анимации — отдельные экшены с понятными именами (Idle, Walk, Run, Attack), зациклены (первый кадр = последнему).

## Стандарт спрайтов (делает render_sprites.py)

- Одна камера, один масштаб и один свет на все кадры и направления — персонаж не «прыгает» и не меняет размер.
- Точка опоры (ноги) в одном и том же месте кадра во всех кадрах.
- Порядок строк: S, SW, W, NW, N, NE, E, SE (S — лицом к зрителю). Столбцы — кадры. `sheet.json` описывает размеры и fps.
- Пиксель-арт: `--pixel` (без сглаживания, жёсткая альфа) и маленький `--size` (32–64). Для мягкого 2D — без `--pixel`, 128–256.
- Проверка глазами: смотри только `preview.png` (одна картинка на все анимации и направления).

## Перед словом «готово» (частые ошибки — проверять всегда)

1. `check_asset.py` на **экспортированном GLB** (не на сцене) вернул `"status": "OK"`; `warnings` из `prepare_glb.py` пустой.
2. Масштаб: высота совпадает с ожидаемой; модель не пересекается с полом и соседними объектами.
3. Ничего лишнего не изменено: не переделаны части, о которых не просили (форма, цвета, окружение).
4. Анимации: все нужные экшены есть в GLB, зациклены, проигрываются у нужной арматуры (в Blender 4.4+ экшену нужен слот).
5. Цвета: в рендере стоит view transform Standard (AgX/Filmic делают цвета тусклыми); нет розового цвета — это потерянная текстура.
6. Экспорт: модификаторы применены (`export_apply`), текстуры упакованы, файл не в десятки МБ.
7. Объекты-дубли через Alt+D (связанные) не правились «по одному» случайно.
8. Описание результата — по фактам из JSON, без «выглядит отлично», если картинку не смотрел.

## Безопасность

- Сервер аддона без пароля и шифрования: только localhost, порт 9876 не открывать наружу.
- `execute_blender_code` выполняет любой Python. Не скачивай и не запускай через него чужие скрипты.
